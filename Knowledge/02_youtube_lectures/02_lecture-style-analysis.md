# 02. 영상별 강의 방식 분석 (추천도 높은 순)

## 분석 근거와 한계

- 영상을 직접 시청하지 않았다. 대신 YouTube 자동 자막(트랜스크립트)을 분 단위로 내려받아 도입부, 전환부, 마무리를 읽었고, 설명란의 챕터와 공개 자료(슬라이드 링크, 노션 치트시트 등)를 함께 보았다.
- 화면에 무엇이 보였는지는 자막 속 발화("이 차트", "화면에 보이는", "터미널로 넘어가서" 등)로 추론했다. 이런 판단에는 "추정"을 붙였다.
- 한국어 자동 자막은 오인식이 많아 흐름 위주로 읽었다.
- 추천도는 "Claude Code 기반 context engineering 강연을, 연구기관 연구자를 포함한 청중에게 한다"는 우리 목적에 얼마나 참고가 되는지를 기준으로 매겼다(★5가 최고). 영상 자체의 품질 순위가 아니다.

## 1. E1. No Vibes Allowed — Dex Horthy (20:31) ★★★★★

- 근거: 트랜스크립트 전문, 설명란.
- 도입: 자기소개와 함께 전작(12-Factor Agents)의 반응을 짧게 언급한다. 곧바로 외부 연구(스탠퍼드의 개발자 10만 명 조사)의 차트로 문제를 제기한다. AI가 코드를 많이 만들지만 상당 부분이 지난주 결과물을 다시 고치는 일이라는 내용이다. 이어 처음 Claude Code를 썼을 때 별 감흥이 없었다는 개인 고백으로 청중의 의심에 공감한 뒤, 팀이 방법을 찾아 처리량이 2~3배 늘었다는 반전으로 넘어간다.
- 구성 흐름: 가장 단순한 사용법(묻고, 틀리면 꾸짖고, 다시 묻기)에서 출발해 한 단계씩 개선한다. 새 창에서 다시 시작하기, 의도적 압축, "dumb zone" 개념(컨텍스트 창의 약 40%를 넘으면 성능이 떨어지기 시작한다는 경험칙), 역할 놀이가 아니라 컨텍스트 통제용인 서브에이전트, Research-Plan-Implement 순이다. 그다음 사례 3개(30만 줄 Rust 코드 수정 성공, 7시간에 3만5천 줄, Parquet Java 실패)를 들고, 온보딩 문서, 점진적 공개(progressive disclosure), 필요할 때 만드는 압축 컨텍스트, 팀의 "mental alignment"로 넓힌다. 끝에 작업 난이도에 따라 얼마만큼의 컨텍스트 엔지니어링이 필요한지를 정리한다.
- 라이브 데모: 없음. 대신 실제 프롬프트, 연구 문서, 계획 파일 화면을 보여주며(추정) 오픈소스로 받아 쓸 수 있다고 안내한다. 사례는 팟캐스트 에피소드와 PR 결과로 입증한다.
- 시각 자료: 연구 차트, 컨텍스트 창을 막대로 그리고 40% 선을 표시한 도식(추정), 영화 "메멘토" 장면(기억 없는 주인공이 문신을 읽는다 = 온보딩 안 된 에이전트), 코드·주석·문서별 "거짓의 양" 차트. 청중에게 차트의 y축이 무엇인지, 코드 리뷰의 목적이 무엇인지 맞혀 보게 하는 질문형 슬라이드를 쓴다.
- 청중과 난이도: 실무 개발자, 중급. 용어는 많지만 비유가 많아 비개발자도 절반 정도는 따라갈 수 있다(추정).
- 마무리: 한 가지만 가져가라며 핵심을 좁힌다. 계획의 잘못된 한 줄은 코드의 잘못된 백 줄이 된다는 것, 그리고 "do not outsource the thinking"이다. 이어 6~12개월 전망(팀과 조직 문화의 문제)을 말하고 채용 홍보로 끝낸다. 질의응답은 없다.
- 우리 강연에 가져올 점: "순진한 사용 → 한 단계씩 개선"의 사다리 구조, 40% 경험칙 같은 기억하기 쉬운 숫자 하나, 성공 사례와 실패 사례를 함께 보여주는 균형, 한 가지만 가져가라는 식의 마무리.

## 2. K1. Claude Code 기초 — 황민호, KIST (2:09:00) ★★★★★

- 근거: 트랜스크립트(앞 12분은 자막 없음), 설명란.
- 도입: 주관 부서가 먼저 교육 전체 구조를 설명한다. 4개 트랙, 월별 연사, 이번 트랙2(바이브코딩 인텐시브 5회)의 회차별 주제(기초, 스킬, 하네스, 플러그인, 행정용 도구). 보직자를 일부러 초청한 이유(윗사람이 알아야 확산된다)도 밝힌다. 좌석 배치, 조교 소개(막히면 손을 들라), 사전 설치 지원 안내가 이어진다.
- 구성 흐름: 개념을 짧게 설명한 뒤 곧바로 따라 하기로 넘어간다. 자막에 따르면 준비한 자료 대신 최신 모델을 조사해 보고서 파일을 만들고 그것을 웹사이트로 바꾸는 과정을 즉석에서 함께 해 본다. 이어 Hugging Face 논문 목록 요약, 디자인 시스템 파일로 "내 디자인 스킬" 만들기, 같은 스킬로 두 번째 사이트(논문 소개)를 만들어 비교하기, 논문 상세 분석 에이전트로 이어진다.
- 라이브 데모: 비중이 매우 높다(강의 대부분). 청중이 각자 노트북에서 같은 프롬프트를 친다. 강사는 에이전트까지 만든 사람이 몇 명인지 물어 진도를 확인한다.
- 시각 자료: 결과물(웹사이트)을 나란히 놓고 비교한다. 슬라이드는 보조 역할이다(추정).
- 청중과 난이도: 연구원 연구자, 보직자, 행정직. 비개발자가 섞여 있으며 입문 수준이다. 질문도 연구 현장의 것이다(한글 문서 HWP 처리, 실험 데이터 형식, Origin 파일).
- 길이: 2시간 넘는 실습. 중간에 토큰 소진으로 진행이 막힌 참석자가 있었다는 언급이 있다.
- 마무리: HWP 스킬 파일과 자주 쓰는 명령어 핸드아웃을 나눠 주며 복습을 권한다. 주관 부서가 다음 회차 일정을 안내한다.
- 우리 강연에 가져올 점: 청중이 연구자라면 "보고서 → 웹페이지", "논문 요약", "HWP 처리"처럼 연구 업무에 붙은 예제가 가장 반응이 좋다. 조교 배치와 사전 설치 지원, 요금제·토큰 한도 사전 안내가 실습형 강의의 성패를 좌우한다.

## 3. K2. Claude Code Harness 심화 — 황민호, KIST (2:02:34) ★★★★★

- 근거: 트랜스크립트, 설명란.
- 도입: 행정 안내(랜선 젠더, 요금제를 Max로 바꾸라는 권고)로 시작한다. 하네스를 말 마구(馬具)에서 온 말로 소개하고, AI가 일하는 시스템을 설계하는 일이라고 한 문장으로 정의한다.
- 구성 흐름: 정의 → 사례(웹툰 제작 에이전트에 품질 검증 에이전트를 붙여 루프를 만든 경험) → 청중 참여 실습(청중에게 최근 연구 주제를 받아 하네스 적용 전후를 비교) → 컨텍스트 관리 → 공개 하네스 모음 소개(정부 지원 사업 계획서 하네스 등) → 결과를 인터랙티브 웹사이트로 시각화 → Codex CLI 연동 스킬 → 질의응답.
- 라이브 데모: 높다. 청중이 준 주제로 즉석 실행한다. 강사가 검증할 수 있도록 너무 어려운 주제는 피해 달라고 요청한다.
- 시각 자료와 비유: 컨텍스트를 주방 작업대에 비유한다. 요리에 필요한 재료만 올려 두면 깔끔하지만, 관계없는 것이 섞이면 소금통에 설탕이 든 것 같은 실수가 난다는 설명이다. 연구자 청중에게 잘 통하는 생활형 비유다.
- 청중과 난이도: K1 수강자 대상 중급.
- 마무리: 실무에서는 데모와 달리 상세 요구 사항을 마크다운으로 따로 정리해 주면 의도가 잘 전달된다는 조언으로 질의응답을 맺는다.
- 우리 강연에 가져올 점: "청중의 연구 주제로 즉석 시연"은 강한 몰입 장치다. 다만 강사가 결과를 검증할 수 있는 주제로 제한하는 안전장치가 필요하다. 주방 작업대 비유는 그대로 빌려 쓸 만하다.

## 4. E2. Claude Code best practices — Cal Rueb, Anthropic (25:53) ★★★★★

- 근거: 트랜스크립트 전문, 설명란.
- 도입: 첫 30초에 목차(무엇인가 → 내부 구조 → 활용처 → 모범 사례)를 예고한다. 이어 금요일 밤에 처음 써 보고 주말 내내 빠져 사내 사용량 순위 1위가 되었고, 그 인연으로 팀에 합류했다는 개인 이야기를 한다.
- 구성 흐름: 비유로 시작하는 멘탈 모델(터미널만 쓰는 고수 동료 "Tony"가 옆에 있는 것) → 내부 구조(도구와 루프로 된 단순한 에이전트, 색인 대신 사람처럼 검색하는 agentic search, 권한 시스템) → 활용처(코드 파악, 생각 파트너, 신규 개발, 테스트, 마이그레이션) → 모범 사례(CLAUDE.md, 권한, CLI 도구, /clear와 /compact로 하는 컨텍스트 관리, 계획과 할 일 목록, 테스트 중심의 "smart vibe coding", 스크린샷, 여러 세션 병행, Esc) → 새 기능 라이브 시연 → 질의응답.
- 라이브 데모: 후반 약 3분. 모델 전환, 도구 호출 사이의 사고(thinking), IDE 연동을 짧게 보여준다. 한 번은 의도와 다른 답이 나오지만 그대로 넘어간다.
- 시각 자료: 구조도(도구, 검색, UI, 권한의 층)와 목록형 슬라이드(추정).
- 청중과 난이도: 개발자, 입문~중급.
- 마무리: 약 4분 질의응답. CLAUDE.md를 여러 개 두는 문제, 지시를 따르지 않을 때의 대처, 여러 에이전트 간 컨텍스트 공유(공유 마크다운 파일에 적어 두라는 답)를 다룬다. 스티커 나눔으로 끝.
- 우리 강연에 가져올 점: 도구의 작동 원리를 알면 더 잘 쓸 수 있다는 이유로 내부 구조를 먼저 보여주는 순서가 context engineering 강연에 잘 맞는다. 에이전트가 세션 사이에 기억이 없으니 CLAUDE.md로 상태를 넘긴다는 논리가 컨텍스트 개념의 자연스러운 입구가 된다.

## 5. E3. Mastering Claude Code in 30 minutes — Boris Cherny, Anthropic (28:07) ★★★★☆

- 근거: 트랜스크립트 전문.
- 도입: 써 본 사람이 있는지 손을 들게 해 청중 수준을 확인한다. 안 써 본 사람에게는 지금 노트북으로 설치해 따라오라고 권한다. 이론과 역사는 하지 않겠다고 먼저 선언한다.
- 구성 흐름: 난이도 계단형이다. 초기 설정 → 코드베이스에 질문하기(가장 먼저 권함. 신규 입사자 온보딩이 2~3주에서 2~3일로 줄었다는 사례) → 코드 편집과 먼저 계획 세우기 → 팀 도구 연결(bash, MCP) → 스스로 결과를 확인할 수단(테스트, 스크린샷)을 주면 반복해서 나아진다는 워크플로 → 컨텍스트 주기(CLAUDE.md 계층, 슬래시 명령, @멘션) → 단축키 → SDK와 파이프 → 병렬 세션 → 질의응답.
- 라이브 데모: 거의 없다. 슬라이드에 실제 프롬프트 예문을 띄우는 방식이다(추정).
- 시각 자료: 프롬프트 예시 슬라이드, 설정 계층 표(본인도 정보 밀도가 높다고 인정), 단축키 참조표.
- 청중과 난이도: 개발자, 입문~중급. 입문자에게 질문부터 시작하라는 안내가 유용하다.
- 마무리: 약 4분 질의응답(bash 안전성, 이미지 입력, 왜 CLI인가, ML 연구자 활용).
- 우리 강연에 가져올 점: 초보에게는 편집보다 질문(Q&A)부터 시키라는 순서가 비개발자 연구자에게도 그대로 맞는다. 연구자라면 "내 코드베이스에 질문"을 "내 자료 폴더에 질문"으로 바꾸면 된다. 각 단계 끝에 "다음 팁"을 한 줄로 정리하는 리듬이 좋다.

## 6. E4. Software Is Changing (Again) — Andrej Karpathy (39:31) ★★★★☆

- 근거: 트랜스크립트(도입·마무리·일부), 설명란 챕터, 공개 슬라이드 링크.
- 도입: 청중(학부·석박사생)을 직접 호명하고, 지금이 업계에 들어가기에 특별한 시기인 이유로 시작한다. 이어 "Map of GitHub" 시각화로 소프트웨어 전체를 한 장에 보여준다.
- 구성 흐름: 소프트웨어 1.0/2.0/3.0 → LLM을 공공재(utility), 반도체 팹, 운영체제에 빗댐 → LLM 심리(사람의 영혼 같은 존재, 들쭉날쭉한 지능, 학습한 것을 다음 날 잊는 기억 문제. 여기서 컨텍스트 창을 작업 기억에 비유) → 부분 자율 앱 설계 → 사람과 AI의 검증 루프 → 테슬라 오토파일럿 경험과 자율성 슬라이더 → 아이언맨 슈트 비유 → 바이브 코딩(본인 앱 MenuGen 사례) → 에이전트를 위한 인프라 → 요약.
- 라이브 데모: 없음. 자기 앱 화면과 사례를 보여준다.
