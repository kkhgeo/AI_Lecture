# How we built our multi-agent research system

- **저자/기관**: Jeremy Hadfield, Barry Zhang, Kenneth Lien, Florian Scholz, Jeremy Fox, Daniel Ford (Anthropic)
- **발행일**: 2025-06-13
- **URL**: https://www.anthropic.com/engineering/multi-agent-research-system
- **자료 유형**: 블로그 (Anthropic 공식 엔지니어링 블로그)

## 핵심 요약

- Claude의 Research 기능을 **orchestrator-worker** 구조로 만든 경험담. 리드 에이전트가 질문을 분석해 전략을 세우고, 여러 하위 에이전트를 병렬로 띄워 각자 검색·평가하게 한 뒤 결과를 종합한다. 마지막에 인용(citation) 에이전트가 출처를 붙인다.
- 성과: Opus 4 리드 + Sonnet 4 하위 에이전트 구성이 단일 Opus 4 에이전트보다 내부 연구 평가에서 **90.2%** 더 좋았다.
- 왜 잘 되나: 하위 에이전트마다 **별도 컨텍스트 창**을 가지므로 한 창의 한계를 넘는 정보를 병렬로 처리하고 압축해 돌려줄 수 있다. 성능 분산의 **80%**가 토큰 사용량 하나로 설명됐다.
- 비용: 에이전트는 일반 채팅 대비 약 **4배**, 멀티에이전트는 약 **15배** 토큰을 쓴다. 따라서 가치가 높은 과제에만 적합하다.
- 컨텍스트 관리: 리드 에이전트는 컨텍스트가 20만 토큰을 넘어 잘릴 수 있으므로 **계획을 외부 메모리에 저장**한다. 긴 대화는 완료된 단계를 요약해 외부에 저장하고, 새 하위 에이전트를 깨끗한 컨텍스트로 띄운 뒤 필요한 기록만 다시 불러온다. 하위 에이전트의 큰 산출물은 외부 저장소에 두고 **가벼운 참조만** 넘긴다.
- 적합하지 않은 경우: 모든 에이전트가 같은 맥락을 공유해야 하거나 실시간 조율이 많은 과제(대부분의 코딩 작업 포함).

## 핵심 개념·용어 정의

- **Orchestrator-worker pattern**: 지휘자(리드)가 과제를 쪼개 작업자(하위 에이전트)에게 위임하고 결과를 합치는 구조.
- **Context isolation / separation of concerns**: 각 하위 에이전트가 독립 도구·프롬프트·탐색 경로를 가져 경로 의존성이 줄어듦.
- **Artifacts pattern**: 산출물을 파일 시스템 등에 직접 저장하고 참조만 전달해 정보 손실과 토큰 낭비를 줄임.
- **8가지 프롬프트 원칙(요약)**: 에이전트처럼 생각하기, 위임 방법 가르치기(목표·출력 형식·도구·경계 명시), 과제 난이도에 맞춰 노력 규모 조절, 도구 설계 우선, 모델 스스로 프롬프트 개선, 넓게 시작해 좁혀가는 검색, 확장 사고(extended thinking)로 계획, 병렬 도구 호출.
- **노력 규모 규칙 예**: 단순 사실 확인은 에이전트 1개와 도구 호출 3~10회, 복잡한 연구는 하위 에이전트 10개 이상.

## 강연에 쓸 만한 포인트

- **도식**: 사용자 → 리드 에이전트(계획을 Memory에 저장) → 하위 에이전트 3~5개 병렬(각자 컨텍스트 창) → 요약 반환 → 인용 에이전트 → 최종 답. "창이 여러 개"라는 시각화가 핵심.
- **수치 슬라이드**: 90.2% 향상 / 토큰이 성능 분산의 80% 설명 / 채팅 대비 4배·15배 토큰 / 병렬화로 복잡한 질의 시간 최대 90% 단축.
- **메시지**: 멀티에이전트의 본질은 "더 많은 토큰을 병렬로, 서로 오염되지 않게 쓰는 방법"이다. 즉 context isolation.
- **Cognition(09번)과 대조**: 읽기·검색 중심 과제는 격리가 유리, 쓰기·결정 공유 과제는 단일 스레드가 유리.
- 인용(1개): 멀티에이전트는 채팅보다 "about 15x more tokens"를 쓴다 (Anthropic, 2025-06-13)

## Claude Code와의 연결점

- Claude Code의 subagent가 이 구조의 사용자판이다. "인증, DB, API 모듈을 각각 별도 subagent로 병렬 조사해줘"로 orchestrator-worker를 재현.
- 계획을 외부 메모리에 저장하는 것은 plan mode의 계획 파일이나 `PLAN.md`에 해당.
- Artifacts pattern: subagent에게 "결과를 `findings/xxx.md`에 쓰고 경로와 3줄 요약만 반환"하도록 지시.
- 대규모 작업은 dynamic workflow나 `/batch`(여러 subagent에 작업 분배)로 확장.
- 비용 경고: subagent를 많이 쓰면 전체 토큰은 늘어난다. 메인 컨텍스트를 아끼는 대신 총량을 더 쓰는 트레이드오프임을 설명.
