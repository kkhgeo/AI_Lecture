# 종합: AI 사용 시 인지 부하 — 줄고, 옮겨가고, 늘어난다 (슬라이드용 정리)

근거 파일: 04_supervising-parallel-agents.md, 05_workslop-and-burden-shifting.md, 06_ai-fatigue-and-workload-surveys.md (2026-10-01 기준). 01–03은 이 폴더에 아직 없음.

## 1. 한 문장 결론
AI는 인지 부하를 없애지 않는다. **작성의 부하를 줄이는 대신, 검증·판단·감독의 부하로 옮기고, 병렬로 돌릴수록 그 부하가 늘어난다.** 관리의 핵심은 "내가 리뷰할 수 있는 만큼만 돌리고, 검증은 기계에, 기억은 파일에 맡기는 것".

## 2. 세 범주
| 구분 | 무엇이 | 근거 |
|---|---|---|
| **줄어든다** | 문법·API 검색, 상용구, 첫 초안, 반복 업무, 낯선 코드 탐색 | 반복 업무를 AI가 대신할 때 번아웃 약 15% 낮음(BCG 2026); 적당한 Copilot 사용 시 NASA-TLX 부하 감소(Brandebusemeyer 외 2025); 자기보고 생산성 +50%(Anthropic 2025-12) |
| **옮겨간다** | 쓰기 → 읽기·검증, 구현 → 명세·판단, 기억 → 통합 | 비판적 사고가 정보 검증·응답 통합·과제 관리로 이동(Lee 외 CHI 2025); 완전 위임 가능 업무는 0–20%(Anthropic); AI 코드임을 알고 검증하면 부하↑·성과↑(Tang 외 2024) |
| **늘어난다** | 여러 세션 감시, 주의 전환, 늘어난 산출물 리뷰, 남이 만든 슬롭 처리 | 업무 증가 이유 1위 "AI 산출물 검토" 39%, 77%가 업무량 증가(Upwork 2024); 고감독 시 정보 과부하 +19%, 도구 4개 이상에서 생산성 하락(BCG 2026); 멀티태스킹 과부하·작업 강화(Berkeley/HBR 2026); 워크슬롭 건당 약 2시간(BetterUp/Stanford 2025) |

덧붙일 함정 두 가지:
- **체감 착시**: 19% 느려졌는데 20% 빨라졌다고 믿음(METR 2025) → 부하·속도는 느낌이 아니라 지표로 확인.
- **역량 침식**: AI로 배우면 이해도 점수 17%p 낮음(Anthropic 2026-01) → 감독에 필요한 실력이 감독 때문에 줄어드는 역설.

## 3. 근거 있는 대응책
1. **먼저 계획·명세, 그다음 실행** — Claude Code 공식 문서: explore → plan → code → commit; 큰 기능은 Claude가 인터뷰해 SPEC.md를 쓰게 한 뒤 새 세션에서 실행. "명세를 정확히 하는 데 쓴 시간이 구현을 지켜보는 시간보다 더 보상받는다." Willison: 자기 명세에서 나온 코드는 리뷰 부담이 훨씬 적다. Cherny: 계획 모드로 시작.
2. **병렬 수 = 리뷰 용량** — Willison: 중요한 변경은 한 번에 하나, 병렬은 조사·프로토타입·저위험 작업만. BCG: 도구 3개 정점. 정량 기준은 없으니 "끝까지 리뷰 못 할 세션은 시작하지 않는다"를 규칙으로.
3. **검증을 자동화해 사람이 루프에서 빠지게** — 공식 문서: 테스트·빌드·스크린샷처럼 통과/실패가 나오는 검사를 주면 "지켜보는 세션"이 "떠나도 되는 세션"이 된다. 검사가 없으면 *사람이* 검증 루프가 된다. 성공 주장 대신 증거(테스트 출력, 실행 명령)를 보여달라고 하라 — 증거 확인이 재검증보다 빠르다.
4. **중단을 줄이고, 리뷰는 몰아서** — Mark(2008): 중단은 속도는 유지해도 스트레스·노력을 올린다. 권한 허용목록·샌드박스로 사소한 승인 요청 제거(문서: 열 번째 승인쯤엔 클릭만 하게 됨), 알림은 "입력 필요"일 때만, 리뷰는 정해진 시간에 묶어서.
5. **새 맥락의 리뷰어 사용** — Writer/Reviewer 패턴, 서브에이전트 적대적 리뷰, `/code-review`. 단, 리뷰어는 찾으라면 항상 뭔가 찾으므로 "정확성·요구사항에 영향 있는 것만" 보고하게(공식 문서). AI 리뷰는 판결이 아니라 센서 데이터, 머지 책임은 사람(Osmani 2026).
6. **CLAUDE.md는 짧게, 맥락은 자주 비우기** — "각 줄마다 지우면 실수가 생기는가?" 아니면 삭제. 비대한 CLAUDE.md는 지시를 무시하게 만든다. 무관한 작업 사이엔 `/clear`, 두 번 고쳐도 안 되면 새 세션.
7. **머리에 들지 말고 적어라** — 세션 이름(`/rename`), PLAN.md, 진행 로그, 실수 기록 문서(Cherny 팀은 Claude의 실수를 git에 있는 문서로 누적). 작업기억 대신 파일이 상태를 보관하면 전환 비용이 준다.
8. **보내기 전에 내가 먼저 검증** — 작은 diff, 목적 설명, 테스트 결과 첨부. 아니면 내 시간 절약이 동료의 2시간이 된다(워크슬롭).
9. **하루 강도 관리** — Willison·Yegge 모두 한두~세 시간이면 고갈된다고 보고(개인 관찰). 고강도 감독 블록 뒤엔 휴식, 학습 목적일 땐 AI에게 설명을 요청하는 방식으로.

## 4. 슬라이드 문구 제안 (36/20/15/12pt 규칙 기준, 제목 1줄 + 본문 3줄)
**안 A (구조형)**
- 제목: AI는 인지 부하를 없애지 않고 옮긴다
- 본문: 줄어든다 — 검색, 상용구, 첫 초안 / 옮겨간다 — 쓰기에서 검증·판단으로 / 늘어난다 — 감시, 전환, 더 많은 리뷰
- 하단 한 줄: 내가 리뷰할 수 있는 만큼만 돌린다

**안 B (주장형)**
- 제목: 가장 피곤한 일은 AI를 쓰는 것이 아니라 감독하는 것이다
- 본문: 감독 요구가 높을수록 정보 과부하 +19% (BCG, 2026, n=1,488) / 업무 증가 이유 1위는 AI 산출물 검토 (Upwork, 2024) / 대응: 계획 먼저 · 검증은 테스트에 · 상태는 파일에
- (수치·출처는 발표자 노트로 이동 가능 — 디자인 규칙상 인용은 노트)

**안 C (행동 지침형)**
- 제목: 병렬 에이전트의 상한은 내 리뷰 용량이다
- 본문: 명세를 먼저 쓰면 리뷰가 가벼워진다 / 통과·실패 검사를 주면 지켜보지 않아도 된다 / 기억은 머리가 아니라 CLAUDE.md·PLAN.md에
